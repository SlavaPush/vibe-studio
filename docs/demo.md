# Демонстрационные запросы к чату

Набор запросов для защиты: простой, сложный, изображение при текстовой модели, запрещённый, контролируемый отказ и попытка получить внутренние данные. Для каждого указаны точный текст, модель в селекторе, ожидаемое поведение и итог проверки.

## Подготовка

1. Открыть https://elbrus-vibe-chat.onrender.com за несколько минут до показа. Сервис работает на тарифе Render Free: после 15 минут без запросов он засыпает, первый запрос ждёт холодного старта около минуты.
2. Войти по личному коду участника. Коды одноразовые: код создаёт владелец (раздел «Коды доступа» в `apps/chat/README.md`).
3. Для каждого сценария создать новый диалог кнопкой создания диалога в списке «Диалоги». Так ответы разных сценариев не смешиваются.
4. Учесть лимит: 5 изображений на участника за 24 часа (раздел «Пределы демоверсии» в `apps/chat/README.md`).

### Ожидаемые события

Последовательности событий задания описаны в `apps/chat/contracts/api.md`, раздел «Последовательности»:

- текстовый ответ: `accepted` → `checks_passed` → `model_selected` → `text_delta` … → `completed`;
- изображение при текстовой модели: `accepted` → `checks_passed` → `model_switched` → `model_selected` → `asset_ready` → `completed`;
- отказ: `accepted` → `refusal`;
- проверка недоступна: `accepted` → `check_unavailable`.

## Контролируемый отказ

Сценарий показывается только на локальном запуске, не на публичном сервисе. Он демонстрирует fail-closed: без успешной проверки запроса основная модель не вызывается.

1. Выполнить `uv sync` в `apps/chat/api` без переменных прокси. Иначе `uv` может не получить пакеты через закрытый прокси.
2. Запустить API чата с переменными прокси только для этого процесса:

   ```bash
   cd apps/chat/api && HTTPS_PROXY=http://127.0.0.1:9 HTTP_PROXY=http://127.0.0.1:9 NO_PROXY=<хост проекта Supabase> uv run uvicorn app.main:app --port 8001
   ```

   Порт `9` закрыт, поэтому соединения с провайдерами моделей не устанавливаются. PostgreSQL не затронута: соединение с ней идёт не через HTTP. Хост Supabase указан в `NO_PROXY`, чтобы запросы к Storage шли напрямую; в прогоне 25 октября 2026 использовано `NO_PROXY=supabase.co`. Выдача подписанных ссылок на изображения в этом режиме не проверялась. Без `NO_PROXY` клиент Storage тоже идёт через закрытый порт, и ссылки на изображения не выдаются.
3. Создать новый текстовый диалог без активных заданий и отправить запрос из таблицы.
4. Ожидание: статус `check_unavailable` и системное сообщение «Проверка запроса недоступна, повторите позже.». Ответ появляется через несколько секунд: исполнитель повторяет проверку с задержкой. В прогоне 25 октября 2026 — 8,2 с.
5. После показа остановить API и запустить его снова без этих переменных.

## Как проверить фактическую модель

- В интерфейсе: подпись под ответом «Модель: … · усилия: …».
- Через API: `GET /api/runs/{id}` возвращает `effective_model` и `effort` задания.
- В БД: таблица `attempts` хранит каждую попытку (`purpose`, `model`, `effort`, `status`). Команда — в разделе «Проверки на реальных API» `apps/chat/README.md`.
- Полный путь через HTTP: `api/scripts/smoke_chat.py` выполняет те же сценарии через запущенный API. Скрипту нужны два неиспользованных кода доступа.
- Только шлюз входа: `api/scripts/eval_gateway.py` проверяет модерацию и классификатор на 26 эталонных запросах.

## Статус проверки

Все сценарии таблицы прогнаны 25 октября 2026 через локальный API чата с реальными моделями: вход по временным кодам доступа в локальной PostgreSQL, новый диалог на сценарий, задание, события SSE и сообщения диалога. Временные коды после прогона отозваны. Публичный сервис этим прогоном не проверялся.

Перед этим в тот же день решения модерации и классификатора проверены отдельным скриптом без HTTP. Решения «пропустить» или «отклонить» совпали с прогоном через API; оценка сложности запроса изображения отличалась (`standard` вместо `trivial`).

Повторить прогон: владелец создаёт два кода в локальной БД (`DATABASE_URL`, не Supabase) и запускает из `apps/chat/api`:

```bash
VIBE_ACCESS_CODE=<код> VIBE_ACCESS_CODE_2=<код> uv run python scripts/smoke_chat.py --base-url http://127.0.0.1:8001 --origin http://localhost:5173
```

Скрипт `smoke_chat.py` не включает контролируемый отказ: этот сценарий проверяется вручную по разделу «Контролируемый отказ».
